# 程序判断与复核（T4）

正式格式见 `system/判断记录格式.md` v0.3。程序只落档可核对的规则结论，不给投资建议；现有七条手写档案没有check，自动程序只在到期时列入人工清单。

## 默认状态

`system/自动判断规则.json` 按PR #6评论，只批准“进入守势后20日起点回撤≥5%”和“成交占比变化代理前五后10日相对沪深300>0”，confidence仍为低。正式启用同时要求enabled=true和非空approved审核说明；兼容旧格式approved=true加approval。市场涨跌方向规则不批准，情绪两条暂不批准。未触发或未批准逐条写跳过原因，零新增是正常状态。

进入守势须有严格前一交易日的市场状态存档，且前日为攻或中性；持续守势不重复落档，缺前日状态不能把首次可见当作进入。

主线“进入确认/进入退潮”两条规则明确“未启用”，等待T15。当前实现无条件跳过这两条；即使隔离回放加 `--include-drafts` 也不会生成主线判断。T15接入时还须审核源格式和转换条件。

## 正式入口（Actions）

```bash
python3 scripts/auto_judgments.py --module 市场状态
python3 scripts/auto_judgments.py --module 散户情绪
python3 scripts/auto_review.py
python3 scripts/check_judgments.py --stats
```

市场状态、散户情绪两个既有工作流在指标完成后分别调用落档/复核/校验，同一repo-writer组串行运行，然后提交判断和运行日志。新增产出登记在运行清单；不改行情库更新工作流。复核由两个入口重复调用，已完成记录跳过。

正式生成取对应源文件的数据日期，不能用机器日期当行情基期；`date`、ID日期为实际北京时间写入日，`check.from`、evidence是数据日。指定非最新数据日的正式补造被拒绝，历史只允许隔离回放。复核日志的data_date表示截至哪个行情日，result.date记录实际写入复核结果的北京时间日期。

ID沿用三位序号：先扫描全部档案当天最大序号再递增；auto_key由规则ID/版本、数据日期、对象代码确定，同事件跨日重跑不新建、不重写原行。规则含义/条件/输入内容改变但版本不变，会报同事件冲突；需要升版本新增记录。

## 隔离回放

```bash
python3 scripts/auto_judgments.py --replay --include-drafts --out-dir logs/test/T4
python3 scripts/check_judgments.py --directory logs/test/T4/judgments --stats
python3 scripts/auto_review.py --directory logs/test/T4/judgments --out-dir logs/test/T4
```

回放信号日期仅取 `data/市场状态/<年月>/<日期>.json` 已有存档，默认截至已存沪深300最新行情日；不会用临时计算的未来指标扩充历史。温度来自当前温度计CSV，仅比较信号日与严格前一交易日，不读取之后的温度决定触发；没有温度历史版本快照，不声称恢复了当日数据修订前的版本。

产出包含隔离JSONL、逐规则生成/跳过原因、未到期/缺行情列表和每规则命中率表。无到期完整样本命中率为null/“暂无”；样本不足30单列“低样本”，30只是报告提示，不是规则批准条件。事件窗口可能重叠，命中率不是独立样本统计，也不是按引擎执行的交易策略回测。

## 审核后的规则口径

|规则|条件|PR #6审核决定|
|---|---|---|
|市场攻势|攻→5日收盘收益>0|不批准；状态用于风险环境|
|市场守势|守→5日收盘收益≤0|不批准；新增进入守势回撤风险规则替代|
|进入守势风险|前一交易日非守→20日起点收盘至最低收盘回撤≥5%|已批准；只在转换日生成|
|行业代理|成交占比变化前5且变化>0→10日相对沪深300超额>0|已批准代理；T8真实资金表接入仍须再审|
|情绪进入冰点|前日≥20且当日<20→20日收益>0|暂不批准，等文本指标满20天及情绪规则升级|
|情绪进入过热|前日<80且当日≥80→20日收益≤0|暂不批准；端点方向不等同路径回撤判断|
|主线进入确认/退潮|未来20日相对沪深300 >0 / <0|未启用；等待T15源数据与阶段转换格式|

行业原字段“资金流入前5”是近5日成交占比减此前20日成交占比，成交额由ETF成交量×收盘价近似。claim和evidence明确写“成交占比变化代理，非真实资金流入”；字段缺失、无代码或变化无效则不生成该排名，不能拿涨幅榜冒充。将来接T8应单独审核并升规则版本。

前三类check为起点至第N个交易日收盘收益，相对为收益差；新增“指数最大回撤”为1−min(窗口close×factor)/(起点close×factor)，包含起点及未来N个交易日，结果非负。此处明确使用起点收盘，不采用窗口内滚动高点。所有类型逐日检查固定窗口，不顺延缺日。现有手写情绪阶段判断可以继续手工落档，程序不擅自变换其含义。

## 全历史研究回放（T4b）

```bash
python3 scripts/auto_judgments.py --full-history
```

输出`logs/test/T4/全历史回放.md`与JSON，读取2016年以来规则检验CSV和2017年以来温度计，不依赖最近才开始积累的JSON存档，不写正式判断。`--full-history`不接受`--date/--module`，`--out-dir`仍须在`logs/test/`。

报告先复现审核评论引用的缓存表，再用已存行情重算起点回撤与进入事件。旧CSV的20日最大回撤是滚动高点口径，不能当作新check；报告并列总样本、完整样本、待到期/缺日、总样本复现占比、完整样本命中率。未到期不填0、不计入完整样本分母。情绪统计只供审核对照，不能借回放启用未获批准规则；资金代理无全历史板块明细，不补造历史。

## 复核保护

- 官方全年休市表覆盖内的工作日优先用于固定窗口，周末总闭市；即使基准CSV缺一天也不把它当休市。官方覆盖外，仅接受已存沪深300历史首末区间内的日期成员；未来年份缺覆盖则待确认，不能猜工作日。
- 逐日核对起点到固定终点的标的/基准行情，缺日、坏factor、重复日期均保留待验证并记录原因；不顺延到后面第N条行情，不补0，不前向填充。
- 复核前核验review_date与固定终点一致；只增加result并更新status，其他字段逐一保留；无check或已有result的记录不覆盖。
- 写入前验证整批记录，按文件原子保存。未改行保持原字节，包括原有换行。多个文件的保存不声称数据库事务，但任一中断可通过auto_key/已有result幂等续跑。
- 新的运行报告继承各上游既有宽限，尚无新步骤独立P95样本，需后续Actions实测校准；已有任务宽限与股票池100天阈值保持原值。
