# 市场推演系统 · 蓝图 v0.1

> 2026-10-22 起草。这份文件定义整个系统长什么样、各模块怎么接在一起。以后加任何模块、改任何格式，先改这里。

## 一、要做成什么

一个**持续理解整个市场**的系统，不是选股器。它要回答五类问题：

1. 大盘现在是攻还是守，资金在追什么、在撤什么
2. 哪些题材和产业在走强，下一步大概率轮到哪里
3. 产业接下来几个季度、一年怎么演变，对应股市怎么轮动
4. 多条产业链交织后，哪些公司被多个**独立驱动**同时点亮，而且还没被定价
5. 以上判断过后到底对不对

它给的是**条件化的概率和情景**（“如果放量且北向回流，进攻板块走强概率较高”），不是一条预测线。它的价值来自两点：比别人更早看到传导，以及每个判断都能事后打分、反过来校准系统。

## 三、三样底座（这是之前缺的）

模块本身不难加，难的是让它们接在一起。下面三条是所有模块都要遵守的约定。

### 1. 统一的数据层

- **只有一个家**：所有数据都放在本仓库 `data/` 下，由 GitHub 服务器定时抓取并提交。电脑不在身边也能运转。
- **按类别分目录**：`data/行情库/`（已有）、`data/财报/`（已有）、`data/股票池/`（已建：命脉股票池页面数据库每日镜像）、`data/新闻/<年-月>/<日期>.jsonl`（已建）、`data/宏观/`（待建）、`data/产业指标/`（待建）。
- **原始数据只追加、不改写**；修正数据另起一条并写明原因。例外：`data/股票池/原始/` 是外部数据库的镜像，每天整体覆盖为最新，历史版本靠 git 记录，变化另记在 `镜像日志.jsonl`。
- **Claude 不手填数据**。实在需要人工补的数字，必须标 `来源=人工` 和出处链接。
- **信息源分三级**：一级是公司公告、财报原文、官方统计；二级是券商研报、行业机构、主流财经媒体转述；三级是自媒体和二手汇总，只能当线索，不能单独支撑判断。

### 2. 统一的判断记录

每个理解层、决策层模块的产出，最终都要落成**一条条判断记录**，追加写进 `judgments/<年-月>.jsonl`。格式见 `system/判断记录格式.md`，检查脚本 `scripts/check_judgments.py`。

规则只有三条：

- 模块之间**只通过判断记录和 `data/` 交流**，不读别的模块的中间文件。这样任何一个模块可以单独重写，不影响其他模块。
- 每条判断必须写清**怎么算对、怎么算错、哪天复核**。写不出来的不是判断，是感想，不入档。
- 判断一旦写入**不修改原文**。观点变了就新写一条，用 `supersedes` 指向旧的那条。

### 3. 一个总控

总控本身不做分析，只做三件事：

1. **汇总**：读最近的判断记录，生成一份「市场全景」，固定栏目——大盘攻守、资金在追什么、各产业所处阶段、交叉候选、冲突清单、到期复核、本周证实/证伪。
2. **查冲突**：比如市场状态判断“守”，产业推演却在推进攻板块；或者同一家公司在两个模块里方向相反。冲突要列出来，由你或 Claude 裁定，而不是悄悄取平均。
3. **管复核**：列出到期的判断，判定后写回结果，并按模块统计命中率。

产出放 `panorama/<日期>.md`，同时推送到手机。

## 四、分工

| 角色 | 负责 | 不负责 |
|---|---|---|
| 程序（GitHub 服务器） | 抓数据、算指标、给图谱打分、列到期复核、统计命中率 | 下结论 |
| Claude | 读数据写判断、做产业推演、维护图谱、写市场全景、判定复核结果 | 手填数据、改历史判断 |
| 你 | 确认方向、校准权重、决定买卖 | 重复性的数据整理 |

原则：**能写成规则的交给程序**，省额度；Claude 只用在需要判断的地方。

## 五、验证与打分

- 每条判断到复核日由程序列出，Claude 对照实际数据判定为 证实 / 证伪 / 部分 / 无法判定，并写一句理由。
- 按模块、按时间尺度统计命中率。某个模块连续表现差，就回头查是数据、规则还是推理出了问题。
- 交叉候选池单独记录，每季度和红利、红利稳健配置在**同一窗口**比较；跑不赢就说明这套方法还没有实际价值，需要改。
- 主观概率也要检验：标“高置信”的判断，命中率应该明显高于“低置信”的。

## 七、已知限制

- 数据来自公开网页，拿不到付费终端的数据，A股估值分位、资金流向会有误差。
- 资金短期走向和大盘走势无法精确预测，系统只给条件化概率和情景区间。
- 驱动图谱里的连线强度初期靠人工判断，需要用营收结构、订单数据和复核结果逐步修正。
- 系统再完整也只是辅助判断，不构成投资建议。
