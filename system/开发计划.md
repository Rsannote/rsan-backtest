## v2 改了什么

1. 加入**主线雷达**（行业层），和大盘层（市场状态、散户情绪、大盘事件库）合成一个"股市大模型"。规则草案见 `system/主线规则.md`，新增 T12–T15。
2. 新增 T11：行情库每次都有几只股票因腾讯 501（限流）缺当天数据。
3. T4、T5、T8、T9 的要求有补充，写在各任务末尾的「v2 补充」里。
4. 原来的任务列表改成**四个阶段**，按阶段推进；阶段内标了哪些可以并行。

## 目标：三层一个模型

```
输入（共用）：行情 · 成交 · 融资 · 宏观利率 · 新闻 · 社区情绪 · 财报和一致预期
   │
   ├─ 大盘层：攻/守/中性 + 情绪温度 + 历史大调整类比      （市场状态、散户情绪、T9）
   ├─ 行业层：每个方向 潜伏/启动/确认/拥挤/退潮 + 主线类比 （T8、T12–T15）
   └─ 个股层：主线里挑公司                                （业绩加速选股、驱动图谱 T7）
   │
   └─ 判断档案（T4 自动落档、自动复核）→ 每周市场全景（T5）
```

大盘层的状态会改变行业层的门槛；行业层的集体拥挤或退潮，又会反馈成大盘层的风险信号。所以两层放在一起做，共用数据，案例库也用同一种格式。

## T2 运行健康检查与告警

**现象**：2026-10-22 16:40 的行情更新到 22:40 还没提交，市场状态停在前一天，没有任何提醒。

**要做**：
- 新建 `system/运行清单.json`：登记每个定时工作流的名字、产出文件、预期更新时间（北京时间）、是否只在交易日运行。现有的全部登记：行情库、市场状态、新闻（四次）、社区情绪、散户情绪指数、股票池镜像（21:37，由外部定时任务写入）、业绩加速选股（只在换股月）。
- 新建 `scripts/health_check.py`：按清单检查每个产出的最新日期是否符合预期（交易日历用 `data/行情库/指数/sh000300.csv`，当天是否交易日的判断写清楚规则），同时读各产出里已有的失败信息（如 `logs/行情库_最新.md` 的失败列表、`data/新闻/状态.json` 的 ok=false）。
- 输出 `logs/健康检查_最新.md`：一张表，每项 正常 / 延迟 / 失败 / 部分失败，附原因。
- 新建工作流每天北京时间 08:20 和 22:30 运行。有异常时**开一个 GitHub Issue**（标签 `告警`，标题写日期和异常项，同一天同一项不重复开，已开的就追加评论）；恢复正常后自动关闭。Rsan 用 GitHub 手机 App 收通知。
- 各工作流失败时也要能被发现：在每个现有工作流末尾加一个 `if: failure()` 步骤，同样开/更新告警 Issue。

**验收**：
- 人为制造一次失败（分支上让某个测试工作流故意失败、或把清单里某项预期时间改早），能看到 Issue 被开出、恢复后被关闭。PR 里贴 Issue 链接。
- 周末和节假日不误报。
- `logs/健康检查_最新.md` 能一眼看出哪项有问题。

## T4 程序判断自动落档与自动复核

**背景**：市场状态和散户情绪每天产出指标，但不落成判断记录，所以无法事后打分。蓝图要求所有模块的结论都变成判断记录。

**要做**：
1. 扩展判断格式（先改 `system/判断记录格式.md`，再改 `scripts/check_judgments.py`）：新增可选字段
   - `auto`: true 表示程序生成；
   - `rule`: 生成它的规则名和版本，例如 `市场状态·云端v1`；
   - `check`: 机器可核对的条件，结构化写法，例如 `{"type": "指数涨跌", "code": "sh000300", "from": "2026-10-22", "to_trading_days": 5, "op": ">=", "value": -0.02}`。支持的 type 先做三种：指数涨跌、指数相对（A 相对 B 的超额）、行业ETF相对沪深300。
2. 新建 `scripts/auto_judgments.py`：在市场状态、散户情绪跑完后运行，按一份**规则表**生成当天的程序判断。规则表放 `system/自动判断规则.json`，你写一个**草案**，在 PR 里说明每条规则的含义，阈值由审核定。草案至少覆盖：
   - 市场状态"攻/守"→ 未来 5 个交易日沪深300 方向；
   - 资金流入前 5 的行业 ETF → 未来 10 个交易日相对沪深300 是否跑赢；
   - 散户情绪温度进入冰点/过热区 → 未来 20 个交易日沪深300 方向。
   - 每条程序判断的 `confidence` 一律"低"，`evidence` 引用 `data/` 下的产出文件路径（level 一级），`claim` 一句话写清楚。
3. 新建 `scripts/auto_review.py`：每个交易日运行，对到期且带 `check` 的判断，用行情库数据自动判定 证实/证伪，追加 `result`（note 写实际数值）。不带 `check` 的只列进待人工复核清单，不动。
4. `check_judgments.py --stats` 按 模块 × 是否程序生成 × 置信度 统计命中率。

**验收**：
- 用 `data/市场状态/` 的历史存档回放（不写入正式 judgments，输出到 `logs/test/`），给出过去一段时间每条规则的命中率表，作为审核定阈值的依据。
- 正式上线后每个交易日新增的判断都能通过 `check_judgments.py`。
- 手写的 7 条判断不受影响。

**v2 补充**：
- 规则表要预留主线雷达的两条规则（T15 完成后启用，现在先写好、标"未启用"）：某行业"进入确认"→ 未来 20 个交易日相对沪深300 跑赢；"进入退潮"→ 未来 20 个交易日跑输。`check` 用"行业ETF相对沪深300"类型；行业层改用申万指数后再加一种"行业指数相对"。
- 判断的 `module` 取蓝图模块名，主线雷达的写 `主线雷达`。
