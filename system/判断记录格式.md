# 判断记录格式 v0.2

所有模块的结论都写成这种记录，一行一条，追加进 `judgments/<年-月>.jsonl`（按写入日期归月）。写完运行：

```bash
python3 scripts/check_judgments.py            # 检查格式
python3 scripts/check_judgments.py --due      # 列出今天之前到期、还没复核的判断
```

## 字段

| 字段 | 必填 | 说明 | 例子 |
|---|---|---|---|
| `id` | 是 | `J-<日期>-<三位序号>`，全局唯一，当天序号递增 | `J-2026-10-22-001` |
| `date` | 是 | 写入日期 | `2026-10-22` |
| `module` | 是 | 产出模块，取蓝图里的模块名 | `产业推演` |
| `scope` | 是 | 判断对象：`{"type": 市场/产业/驱动/公司, "id": ..., "name": ...}` | `{"type":"公司","id":"300308","name":"中际旭创"}` |
| `horizon` | 是 | 时间尺度：日 / 周 / 月 / 季 / 年 | `季` |
| `claim` | 是 | 一句话判断，必须能被证实或证伪 | `三季报利润和毛利率守住，订单没坏` |
| `direction` | 是 | 市场类用 攻/守/中性；其他用 看多/看空/中性 | `看多` |
| `confidence` | 是 | 高 / 中 / 低 | `中` |
| `evidence` | 是 | 至少一条：`{"text", "source", "level": 一级/二级/三级}`；三级来源不能是唯一依据 | |
| `verify` | 是 | 怎么算对：可核对的具体条件 | `三季度毛利率不低于上半年的46.59%` |
| `falsify` | 是 | 怎么算错：至少一条 | `["三季度毛利率明显下滑"]` |
| `review_date` | 是 | 复核日 | `2026-10-30` |
| `depends_on` | 否 | 依赖的其他判断 id；上游被证伪时下游要一起复查 | `["J-2026-10-22-001"]` |
| `drivers` | 否 | 关联的图谱驱动 id | `["D1"]` |
| `supersedes` | 否 | 取代哪条旧判断（旧判断原文不改） | |
| `status` | 是 | 待验证 / 证实 / 证伪 / 部分 / 无法判定 / 已被取代 | `待验证` |
| `result` | 复核后必填 | `{"date", "status", "note", "evidence"}` | |
| `auto` | 否 | 布尔值；true为程序生成，缺省为手写 | `true` |
| `rule` | 程序生成必填 | 规则名与版本，不随复核改写 | `市场守势方向·草案v1` |
| `check` | 否 | 自动复核条件，详见下文；缺省只列人工复核 | |
| `auto_key` | 程序生成必填 | 规则/数据日期/对象的16位事件摘要，用于跨运行日去重 | |

## 程序条件（v0.2）

三种类型均用固定起点收盘到第N个交易日收盘的收益，价格为 `close × factor`；收益单位为比例（0.02=2%），相对收益为两个简单收益之差，不是收益比。不是路径内最大回撤，也不是交易策略回测。

```json
{"type":"指数涨跌","code":"sh000300","from":"2026-10-22","to_trading_days":5,"op":">=","value":0}
{"type":"指数相对","code":"sh000300","benchmark":"sh000001","from":"2026-10-22","to_trading_days":5,"op":">","value":0}
{"type":"行业ETF相对沪深300","code":"512880","benchmark":"sh000300","from":"2026-10-22","to_trading_days":10,"op":">","value":0}
```

- `code`：指数类型用行情库 `指数/<code>.csv`；行业ETF用 `ETF/<六位代码>.csv`。比较符仅支持 `> >= < <=`，value须为有限数字，N须为1–250的整数。
- `check.from` 是证据对应的数据日期，不晚于实际写入日期date；review_date为起点之后第N个交易日（起点不计数）。午夜后运行时date/id用北京时间实际写入日，行情基期仍用check.from。工作日需有官方日历覆盖或已存沪深300日历证据，不猜节假日。复核时重新核对固定终点；不能用“第N条可用行情”顺延缺失日。
- 起止点及整个交易日窗口缺任一标的行情、factor无效、尚未到期或终点日历不能确认：保留待验证，在复核日志说明，不补0、不前向填充。无check的记录只列人工复核，不自动改为无法判定。
- 程序记录沿用 `J-<写入日期>-<三位序号>`，写入前扫描全部档案当天最大序号再递增；超过999条报错，不覆盖。auto_key摘要为规则ID/版本、数据日期和对象代码的16位SHA256前缀。同auto_key即使跨午夜重跑也只保留第一次记录，冲突报错。date及运行日志使用北京时间；隔离历史回放的复核日可早于写入日，仍不得早于check.from。
- 固定复核窗口优先使用官方休市表覆盖区间内的工作日（周末总是闭市）；这样官方交易日即使沪深300CSV缺报也不会被误当休市。官方覆盖以外，仅在已有沪深300历史首末日期内按日期成员判断；两者均未覆盖则报待确认，不猜未来工作日。此口径用于计算判断窗口，不改变T2健康检查的历史成员优先口径。
- auto=true须有rule与check，confidence恒为低，evidence全部为 `data/` 仓库相对路径、level=一级；路径不得含 `..`。草案未批准前不得写正式judgments，隔离回放仅在 `logs/test/`。
- 正式启用须规则同时 `enabled=true`、`approved=true`，记录审批说明并升版本。主线雷达两条规则当前标“未启用”，依赖T15，隔离草案开关也不能启用。
- 复核只更新status、增加result，其他字段逐一保留；result须含date/status/note/evidence，status与记录status一致，note记录实际收益、起止日及判定条件。

## 规则

- 原文一旦写入不改。复核只追加 `result` 并更新 `status`；观点变了另写一条并填 `supersedes`。
- `claim` 写不出 `verify` 和 `falsify` 的，不入档。
- `confidence` 要诚实：复核时会按置信度分组统计命中率，用来检验系统自己的把握程度。
- 不构成投资建议的提示由总控在全景里统一加，记录里不用重复写。
