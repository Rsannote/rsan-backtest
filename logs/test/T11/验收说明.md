## 实现与工程草案

主循环结束后，仅对本次明确“失败”的标的串行补抓，未轮到项不补抓。默认最多2轮，每轮前等待60秒，请求及标的间隔2秒，单标的120秒，含等待的额外总预算最多600秒。参数可配置，但总预算不可超过600秒、请求间隔必须慢于原0.8秒。

每个补抓标的在子进程和其CSV/分红表副本中调用原update_one；超时终止子进程，不把临时结果回库。成功后校验结构、日期、行数、末因子及CSV/分红表SHA，再原子晋升；中途晋升异常回滚。update_one、复权、原CSV写入、增量比较与T1未知首年前缀保护的AST保持与已合并main一致。

日志增加主循环失败数、补抓成功数/轮数/尝试次数、实际增加耗时及“补抓成功”名单。最终失败保留原始失败与各轮原因；成功结果写回原状态表流程。

## 父任务应安排的Actions步骤

工作流使用repo-writer串行组，安装原有pandas/numpy；验收作业授予contents:write与actions:read，GITHUB_TOKEN供只读收集Actions元数据。新工作流由父任务维护。

```bash
set -o pipefail
git fetch origin main
python3 -m unittest discover -s tests -v 2>&1 | tee logs/test/T11/Actions离线测试.txt
md5sum -c engine/ENGINE_MD5.txt
python3 scripts/verify_t11_retry.py --source-ref origin/main --codes sh000300,600872 --inject-501 600872
```

验收助手要求GITHUB_ACTIONS=true，先从最新main本地clone到隔离目录，再运行分支代码。每次都重新收集Actions元数据，在同一个隔离副本复跑run_delay_stats.py；不apply，不覆盖正式清单/统计，检查股票池100天freshness政策整项保留。输出和原始Actions快照均写入本次logs/test/T11/执行/目录。

注入只影响主循环一次；补抓子进程仍访问原腾讯/新浪源。若最终仍失败、主程序非零，或注入代码未出现在补抓成功名单，保存证据并使CI失败，不能用绿色CI冒充恢复。

仅复跑统计而不请求行情：

```bash
python3 scripts/verify_t11_retry.py --source-ref origin/main --stats-only
```

完整真实交易日验收，在该执行日收盘后运行；默认关键标的是沪深300与四只近期501标的，可用--codes明确指定关键标的，--all仍运行完整清单：

```bash
git fetch origin main
python3 scripts/verify_t11_retry.py --source-ref origin/main --all
```

资格要求：执行日为确认交易日、收盘后开始且当日完成、关键标的实际last到执行日、最终失败0、补抓额外耗时不超过600秒。按数据日期去重，只累计连续交易日，且仅累积update_hangqing.py、验收助手与run_delay_stats.py三脚本SHA256实现指纹完全相同的记录。文档或每日请求提交不改变指纹；修代码后不能混用旧版两天加新版一天，旧证据保留但不计入新版本。永久错误的非限流例外由审核判定，助手不自动算通过。周六全量轮换可用--all --full --rotate做独立烟雾，但周末不计入3个交易日。

正式data、engine、archive、judgments、运行清单及正式延迟统计的前后SHA256保存在“保护哈希.json”；结果含本次实际数据日期、主循环失败数、重试名单、最终失败原因、实际增加耗时与资格不足原因。

## 延迟校准保护

run_delay_stats.py的dry-run保留股票池整项政策，历史每日镜像样本不能改回逐交易日。正式--apply-manifest需有至少28天可审计历史与任务首个真实成功证据，并在近28天四个7日段各有成功样本；不足直接拒绝，清单原字节保留。起点取完整生产历史，不要求已裁剪28天窗口内的样本首尾再跨28天，避免永远无法应用。

满足保护后仅更新日/高频任务，缺样本/稀疏换股任务保留现有参数。当前不足4周，只确认隔离统计可复跑，不更新任何正式宽限。
