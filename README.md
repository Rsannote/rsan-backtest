# rsan-backtest

Rsan 的固定口径回测仓库：引擎、数据、策略和每次回测的存档都放在这里，任何一次对话拉下来就能原样复现。

从 2026-10-22 起，这里也是**市场推演系统**的家：系统怎么分层、模块怎么接，见 [`system/蓝图.md`](system/蓝图.md)。接下来的开发任务见 [`system/开发计划.md`](system/开发计划.md)，由代码助手按 [`AGENTS.md`](AGENTS.md) 的约定实现、Claude 审核。

| 目录 | 放什么 |
|---|---|
| `system/` | 蓝图、判断记录格式等系统约定；加模块或改格式先改这里 |
| `judgments/<年-月>.jsonl` | 判断档案：各模块的结论，一行一条，到期复核打分。检查：`python3 scripts/check_judgments.py --due` |
| `graph/` | 驱动因素图谱（驱动→产业→环节→公司，带强度和时滞） |
| `data/股票池/`、`data/新闻/`、`data/市场状态/` | 股票池镜像、新闻库、市场状态（见下文“数据”） |

## 目录

| 目录 | 放什么 | 规则 |
|---|---|---|
| `engine/` | 回测引擎 `backtest.py`（v1.2） | 口径写死；改口径要升版本号并更新 `ENGINE_MD5.txt`；核对命令 `md5sum -c engine/ENGINE_MD5.txt` |
| `data/日线_<日期>/` | 后复权日线 CSV，列 `date,open,close,factor` | 一经用于回测就不再改动；更新数据另建带日期的新目录 |
| `strategies/<策略名>/` | 策略 .py 和它读取的所有输入文件 | 策略只读自己文件夹里的文件；方案用中文名，旧代号放括号里 |
| `archive/<日期>_<简称>_v<版本>_<本金>/` | 每次回测的完整结果 | 不覆盖、不删除；目录已存在就换新名 |
| `scripts/` | 数据抓取和检测脚本 | |

## 固定口径（v1.1 起，v1.2 未改口径）

后复权、分红再投资；收盘出信号、次日开盘成交；佣金万一免五最低 0.1 元；股票卖出印花税 0.05%、沪市过户费 0.001%，ETF 免；一手 100 股，按真实股价取整；现金不计息。

每次回测必须写明本金：标准口径 100 万用于方案之间比较，涉及实盘时再按真实资金另跑一次。策略和两个基准（红利 510880 持有、红利稳健配置）使用同一窗口、同一交易日历。

## 跑一次回测

```bash
python3 engine/backtest.py \
  --data data/日线_<日期> \
  --strategy strategies/<策略名>/<策略>.py \
  --capital 1000000 \
  --start YYYY-MM-DD --end YYYY-MM-DD \
  --out archive/<日期>_<简称>_v1.2_100万
```

跑完后：
1. 进入结果目录运行 `bash repro/rerun.sh`，`cmp nav.csv rerun/nav.csv` 必须完全一致，再删掉 `rerun/`。
2. 查看 `report.md` 里的平均现金占比、数据提醒。
3. 结论记进「我的炒股体系」文档的回测案例档案。

## 数据

### 行情库（自动更新，不用每次重新拉）

`data/行情库/` 存着 `data/标的清单.csv` 里所有标的的日线：4 个基准 ETF、6 个常用 ETF、7 个指数、命脉股票池全部 123 只（含已淘汰的，回测选股时可以避免幸存者偏差），从 2005 年起。

- **自动更新**：GitHub 服务器每个交易日北京时间 16:40 增量更新（`.github/workflows/update-hangqing.yml`）；每周六把约四分之一标的全量重抓，和已存数据逐日核对，四周轮完一遍。不用开电脑。
- **看更新情况**：`logs/行情库_最新.md`（失败、停牌、新分红、历史数据被改动都会写在这里）；`data/行情库/状态.csv` 是每个标的的起止日期和最近一次分红。
- **存的是什么**：`<ETF|股票|指数>/<代码>.csv` 列 `date,open,high,low,close,volume,factor`，价格是**不复权原始价**，factor 是后复权系数（后复权价 = 原始价 × factor，乘法复权、分红再投资）。`分红表/<代码>.json` 是新浪的原始分红表，因子可以离线重算。
- **数据来源**：腾讯 K 线（不复权日线）+ 新浪 hfq.js（股票给累计复权因子；ETF 给累计每份分红和份额折算比例）。东财在 GitHub 服务器上连不上，也不用。2026-10-21 核对：4 个基准 ETF 与电脑上核对过的数据逐日一致（最大相对差 3×10⁻⁷）；长江电力、美的、紫金、中际旭创的除权日隐含分红与实际分红方案一致。
- **全量抓取起点（T1）**：已有标的从已存腾讯日线的首个年份开始；首次建库没有首年时分段探测，前缀 501 先按限流退避尝试 3 次，连续失败后暂记无数据。首个有效分段的首条日期距起点不超过 10 个自然日时，重新探测上一空段；补回的历史若也贴近边界则继续向前核验，仍不确定就报错、不写文件。正常增量、已有首年或已取得有效日线后的 501 仍按原有重试规则报错；全部无数据不写入。日期取已存腾讯日线，不手填，复权算法不变。
- **失败补抓（T11）**：主循环结束后只重试本次明确失败的标的，保留原来的全量/轮换/增量模式；未轮到的不算失败重试。最多两轮，草案为每轮先等60秒、串行请求间隔2秒、单标的硬截止120秒；补抓总预算最多600秒，包含等待。参数见 `--retry-rounds`、`--retry-wait`、`--retry-pace`、`--retry-item-timeout`、`--retry-budget`，`--retry-rounds 0` 可禁用。子进程只写隔离副本，成功且文件校验通过才晋升，超时或坏文件不污染原库。日志分开列主循环失败、补抓成功和最终仍失败的标的，三交易日真实验收记录放 `logs/test/T11/`。
- **指数只有价格指数**，不含分红，只适合做择时信号，不要当持有收益。

### 运行健康检查与告警（T2）

`system/运行清单.json` 登记全部定时产出的计划时刻、截止宽限、是否仅交易日及产出文件，包括每日四次新闻和信息源、散户情绪指标、外部股票池镜像和换股月选股。每天北京时间 **08:20、22:30** 运行，报告为 `logs/健康检查_最新.md` 和同名 JSON；行情日志中的轮流 501 按已有失败名单列为“部分失败”，显示代码和名称，补抓由 T11 处理。

交易日优先用沪深300日线首末日期内的实际成员；周末闭市；历史尚未覆盖的工作日使用 `system/交易所休市.json` 中由程序从上交所年度公告提取的全年休市安排。跨年无有效覆盖会明确失败，不把“缺今天行情”猜成休市。公告格式不完整时拒绝覆盖已有日历。宽限由 `scripts/run_delay_stats.py` 从近28天生产 Git 提交及成功定时运行统计，按最近秩 P95 加实测尾部余量配置，每项保留统计日期、P95、余量和源提交。收盘相关产出在08:20核对严格上一交易日，22:30只要求已过统计截止的产出；新闻/热榜按最近一次成功产出距今的统计门槛检查，不逐slot误报。已有失败/部分失败证据始终单列。

异常以“告警”标签开 Issue，同一天同一项目复用并追加评论；同日恢复再失败会重开原 Issue。产出恢复后自动关闭；工作流故障还须核对故障之后的成功运行，按完成运行的更新时间判断，避免旧运行重跑造成误关闭。全部现有工作流均接入 `if: failure()`，checkout 失败时可通过同一提交的 GitHub API 下载独立告警脚本执行。工作流使用默认 `GITHUB_TOKEN`，健康任务需要 contents/ issues 写权限及 actions 读权限，无新 Secret。

可离线生成报告：`python3 scripts/health_check.py --json-out logs/健康检查_最新.json`。命令只读各数据产出，写健康报告；告警联网与日历网络刷新仅在 Actions 执行。延迟分布见 `logs/运行延迟统计.md/json`，两周逐时点回放见 `logs/test/T2/延迟校准/历史回放.md/json`。可用记录少于28天时明确覆盖范围；这是历史样本内验收，未覆盖日期与未来检查不计作“零误报”。统计脚本不在健康任务中自动放宽门槛；更新须重新生成并审查清单。验收与模拟故障记录放在 `logs/test/T2/`，入口见 `logs/test/T2/验收.md`。Issue 去重读取禁缓存的完整列表并保留成功写入响应，避免标签列表延迟造成重复告警。

T11 另验证延迟统计脚本能在隔离副本复跑，输出在 `logs/test/T11/`，本次不更新正式清单宽限。`--apply-manifest` 必须通过四周生产观察和成功样本覆盖检查；尚无足够样本的任务保留原参数，股票池审核定的100天季度新鲜度政策也不被延迟校准覆盖。

### 股票池镜像（每天自动）

`data/股票池/` 是命脉股票池页面数据库的镜像：`原始/<集合>/<id>.json` 与数据库逐条一致，`股票.csv` 是一只一行的平铺表（第一层状态、类型、市值、计划状态），`镜像日志.jsonl` 记每次的增删改，`状态.json` 是最近一次检查时间。页面数据库 GitHub 服务器读不到，所以由定时任务「股票池数据库每日镜像」（北京时间每天 21:37）导出后运行 `scripts/pool_mirror.py` 提交；导出不完整（某集合变空或少了两成以上）时整次不写入并推送提醒。股票池仍以页面为准，这里只读。

### 市场状态（每个交易日自动）

`data/市场状态/最新.md` 是最新一天的大盘攻守、冷热、主线、资金流向和行业 ETF 明细；`最新.json` 同内容给程序用，`<年-月>/<日期>.json` 是每天的存档，`日指标.csv` 是每天的成交额和涨跌停（2014 年起，实时接入前为回补估算），`融资余额.csv` 是 2010 年起的融资余额。规则见 `system/市场状态规则.md`（云端v1，附旧版进/守/空对照和历史检验结论）。

- 行情库每天 16:40 更新完后，`.github/workflows/market-state.yml` 自动运行 `scripts/market_state.py`，实时取两市成交额、涨跌停炸板和融资余额。
- 板块用标的清单里 group=行业ETF 的 34 只 ETF 近似，note 里写了风格和对应的命脉股票池行业。
- 历史回补：`scripts/market_state_backfill.py`；规则检验：`scripts/market_state_check.py`，结果在 `logs/市场状态_规则检验.md`。

### 新闻库（每天四次自动）

`data/新闻/<年-月>/<日期>.jsonl`，一行一条，只追加。来源：新浪 7x24、华尔街见闻（A股、全球）、东方财富 7x24 四个快讯源；国务院、发改委、统计局、人民银行、证监会官网发布；股票池全部公司在巨潮的公告。GitHub 服务器北京时间 07:47、12:13、16:23、21:11 运行 `scripts/fetch_news.py`（`.github/workflows/fetch-news.yml`）。

- 每条按 `system/新闻归类.json` 的关键词打标签（宏观类型、驱动 D1–D6、12 个行业、池内个股）和重要度 1–3；这是程序初分，判断时以原文为准。改归类直接改这个 json。
- 不同来源的同一条快讯只保留一条，转载的记 `dup_of` 且不存正文。
- 最近 24 小时重要度≥2 的条目和标签计数：`data/新闻/最新.md`；各来源成败：`data/新闻/状态.json`。
- 财联社、上交所、深交所在 GitHub 服务器上连不上，没有接入。

### 社区情绪与散户情绪（每个交易日自动）

`data/社区情绪/<日期>/` 是当天的热度榜（东财人气/飙升榜、同花顺热股/概念榜）、上证股吧帖子、tophub 财经热榜（含股吧、雪球、集思录）、微博热搜，以及股吧、集思录热门帖子的正文和回复（`讨论摘录.md` 给人读，`讨论原始.jsonl` 给程序算）。每个交易日 15:37 由 `.github/workflows/community-sentiment.yml` 抓取。

「市场状态」跑完后，`.github/workflows/sentiment-index.yml` 按 `system/情绪规则.md`（v1）算情绪温度计和文本指标：`最新.md` 是最新一天的读数，`触发.json` 写是否触发，`温度计.csv`（2017 年起，与回测案例 78 同口径）和 `文本指标.csv` 是历史。触发日由定时任务「散户情绪·触发判读」做阶段判读并推送，每周五「散户情绪·周报」总结一周。

### 回测前：切一个固定快照

回测**不要直接读行情库**（它每天在变）。先切出一个固定目录，再用它回测：

```bash
python3 scripts/snapshot.py --codes 600900,000333          # 基准 4 只 + 指定标的
python3 scripts/snapshot.py --groups 股票池 --end 2026-09-30  # 按清单分组，截止某天
python3 scripts/snapshot.py --all                           # 全部
```

输出 `data/日线_<截止日>/`，列 `date,open,high,low,close,volume,factor`（open/high/low/close 为后复权价），引擎直接读。基准 4 只总会带上。目录已存在时：内容相同就复用；不同就自动换名 `_2`、`_3`，旧目录不动。快照目录要和回测存档一起提交进仓库。

### 加新标的

在 `data/标的清单.csv` 加一行（code,name,type=ETF|股票|指数,group,note；指数的 code 写成 `sh000300` 这种带前缀的），然后把 `jobs/run.txt` 改成 `update_hangqing.py --codes <代码>` 推送，几分钟后 GitHub 服务器就会抓好提交回来。

### 在 GitHub 服务器上运行脚本

云端对话里连不上行情网站，需要联网的脚本都交给 GitHub 服务器跑：把 `jobs/run.txt` 改成一行「脚本名 [参数]」推送即可（`.github/workflows/push-task.yml`），产出的 `logs/`、`data/` 会自动提交回仓库。

### 旧数据

`data/日线_2026-10-20/` 是之前用 `scripts/fetch_etf.py` 生成、已和电脑数据核对过的四个基准 ETF，保留不动，旧回测靠它复现。注意：不要使用不复权数据，也不要使用东财 ETF 的加法"后复权"。

## 业绩加速（v3）换股选股

由 Mac 上 `~/股票助理/v3_select.py` 迁移到 GitHub 服务器（2026-10-21），**选股规则一字不改**，不再需要开电脑。

- **自动运行**：`.github/workflows/v3-select.yml`，每年 5/1、9/1、11/1 起连续三天北京时间 10:07 运行；本期已出正式名单就跳过，失败了第二、三天自动重试。
- **结果**：`data/v3/<换股日>.json`、`data/v3/latest.json`、`data/v3/最新名单.md`；运行日志 `logs/v3_最新.md`。资金、持股只数在 `data/v3/config.json` 里改。上期名单当作"上期持仓"，用于算卖出/买入/继续持有。
- **取数**：申万成分、同花顺年报和单季财报、新浪分红（akshare）；实时价和总市值、成交额和上市年限用腾讯（东财在 GitHub 上连不上）。成交额 = 周成交量×周收盘价，近似。申万网站取不到时用存档 `data/v3/申万成分.json`。
- **筛选顺序**：规则都是"同时满足"，先用财报筛，最后只对满足季报加速条件的几十只查腾讯周K（腾讯在 GitHub 上限流严重），结果与原版顺序相同。
- **失败保护**：行业成分不足 1500 只、第一层通过 0 只或超时没跑完时，不写正式名单，只留 `失败_<换股日>.json`，工作流标为失败。
- **测试**：`jobs/run.txt` 写 `v3_select.py --test --asof=2026-09-01`，结果写到 `logs/v3_test/`，不影响正式名单。2026-10-21 用 9/1 那期测试：2353 → 市值达标 717 → 第一层 394 → 季报加速 61 → 成交额与上市年限达标 54，用时约 62 分钟。
